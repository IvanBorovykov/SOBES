# История версий

## v0.4.5 — захват звука Discord

- Во время речи из Discord через динамики Mac ScreenCaptureKit возвращал нулевые сэмплы, хотя Core Audio видел активный аудиовыход Discord. Диагностический process tap в тот же период получал ненулевой сигнал.
- На macOS 14.2+ системный звук теперь читается через приватный Core Audio process tap с преобразованием в PCM 16 кГц mono; ScreenCaptureKit сохранён для старых версий macOS.
- Выход звука не переключается и не заглушается; приватные объекты захвата освобождаются при остановке helper.
- Проверено: сборка Swift, 108 автоматических тестов, преобразование воспроизводимой речи в 20-мс PCM и штатное завершение helper. Проверка Bluetooth и смены выходного устройства в эту серию не входила.

## v0.4.4 — проверка голосовых вопросов по проекту

- Создан работающий учебный проект из пяти Python-файлов (754 строки) и воспроизводимые API-пробы с голосовыми вопросами: поиск BBB, оба вызова, скидки/доставка, rollback, отмена/выручка, отсутствующая функция, смена вопроса.
- Прежняя 3.5 Flash-Lite LOW ошиблась в четырёх из девяти основных ответов. Файловый режим переведён на отдельную 3.5 Flash-Lite HIGH с уточнённой инструкцией → 3.8 Flash LOW.
- Финальная HIGH-серия: 9 обычных +7 тихих/зашумлённых вопросов с правильной основной логикой и подтверждающими ссылками. Первый текст: медианы3,33/3,92 с; не обещание скорости любого запроса.
- Пустой файловый ответ пробует резерв и затем показывает ошибку с правильной горячей клавишей; ложного успешного завершения нет.
- Исправлена ротация при проектном404: запрет только конкретной пары ключ/модель, переход к следующему ключу, без переотправки уже начатого ответа.
- Реальная проба четырёх профилей: 429 →404 →404 → правильный ответ; следующий вопрос сразу на доступном профиле. Доступ и файловая генерация каждого нового профиля проверены без записи секретов в проект.
- 108 автоматических тестов; полный отчёт и сырые данные в benchmarks/files_project/REPORT.md.


## v0.4.3 — запуск звука после временного отсутствия дисплея

- Пустой список дисплеев ScreenCaptureKit больше не завершает helper навсегда: запрос повторяется каждые 2 секунды в фоне.
- Пока дисплей недоступен, показывается состояние ожидания; после появления дисплея READY снимает блокировку аудиозапросов.
- Отказ разрешения и ручная остановка захвата сохраняют прежнее явное поведение, без автоматического обхода.
- Проверено: 102 теста; настоящий системный PCM с ненулевым сигналом; нативная проба двух пустых ответов списка дисплеев с последующим READY.


## v0.4.2 — модели «Только звук» по результатам замеров

- Выполнены API-пробы 45 идентификаторов (36 REST + 9 Live) из каталога 63; остальные исключены по назначению. Сохранены скрипты, сырые результаты, точные аудиовопросы и полный [отчёт](benchmarks/REPORT.md).
- Live 3.1 minimal сохранена: путь ⌥Q 6/6, медиана первого текста 0,939 с; 3.8 Live — 1,694 с. Это короткие синтетические пробы, не обещание времени реального звонка.
- Голосовой REST-резерв переведён на 2.5 Flash budget0 → 3 Flash Preview minimal; в повторной серии медианы 1,285 и 1,599 с.
- Отдельный голосовой тайм-аут 10 с; переход до первых слов, частичный ответ не переотправляется. Экранные/файловые запросы сохраняют свои модели.
- Для резерва сохраняется звук до ожидания Live, чтобы начало вопроса не вытеснялось из аудиобуфера.
- 101 автоматический тест; дополнительные настоящие API-пробы обоих резервов через код приложения.


## v0.4.1 — голос собеседника из звонка напрямую

- Добавлен выбор «Микрофон» / «Звук компьютера» в настройках, с сохранением источника.
- Нативный ScreenCaptureKit захватывает системное аудио без BlackHole, в том числе при выводе в наушники.
- Helper передаёт только PCM 16 кГц mono, чанки 20 мс; без кадров экрана и без записи на диск.
- Смена источника очищает аудиобуфер и Live-контекст. Ошибки захвата/разрешения показываются явно, подмены микрофоном нет.
- Подготовка/сборка helper идёт в фоне; интерфейс настроек остаётся доступным.
- Проверено 96 автоматических тестов; нативное меню и реальная цепочка: воспроизведение синтезированного вопроса → системный захват → Gemini Live → правильный полный ответ.


## v0.4.0 — голосовые вопросы по файлам

- «Файлы…»: выбор, сохранение списка и удаление материалов из контекста без удаления оригиналов.
- «Вопрос по файлам ⌥A»: последний голосовой вопрос и выбранные документы, без снимка экрана.
- Ответы со ссылками на страницы PDF / строки текста и обозначениями источников F1/F2.
- PDF с текстом, DOCX (основной текст и таблицы), текстовые файлы; до 20 файлов и 300 000 символов контекста.
- Неизвлекаемые страницы PDF требуют OCR; ошибки и превышение лимитов не скрываются.
- Аудио фиксируется в момент нажатия; кеш документов обновляется при изменении файлов.
- Отдельный запрос: 3.5 Flash-Lite low, резерв 3.8 Flash, тайм-аут 60 секунд; файлы не попадают в постоянную Live-сессию.
- Сохранена защита v0.3.1 от прерывания генерации новой речью.
- Проверено: 88 автоматических тестов, нативное окно выбора материалов; независимое ревью, замечания исправлены.
- Реальный тест: синтезированный голосовой вопрос + небольшой вымышленный документ, правильный ответ и ссылка; первый текст 1,42 с, весь ответ 1,56 с. Это отдельная проба. 3.8 в двух пробах вернула сетевой тайм-аут.

## v0.3.1 — ответ не обрывается от нового звука

- Основа: v0.3.0, одна голосовая Live-сессия, Opus для экранных REST-запросов.
- Gemini получает `NO_INTERRUPTION`: новая речь не отменяет текущую генерацию.
- Локальные и серверные события начала речи не стирают текст, пока ответ не завершён.
- Конец генерации не подменяет конец хода: ответ защищён до `turn_complete`.
- Завершённый текст сохраняется для открытого окна даже при немедленном начале следующего вопроса.
- Следующий ответ получает отдельный ход и не приклеивается к предыдущему.
- Неожиданное прерывание сервером отображается как ошибка с сохранением уже показанной части.
- Проверено: 71 тест; реальная API-проба с искусственным шумом после первых слов завершилась полным ответом.


## v0.3.0 — одна Live-сессия и сжатое голосовое

- Одна постоянная Live-сессия только для ⌥Q; изображения туда никогда не отправляются.
- ⌥Z и ⌥X используют отдельные REST-запросы со свежим снимком и аудиобуфером.
- Удалены второй фоновый контекст, фоновая отправка снимков и дополнительная Live-сессия резерва.
- Голосовые REST-запросы используют OGG/Opus 24 kbps; ffmpeg кодирует в памяти с минимальной сложностью.
- Обрезается только цифровая тишина по краям с запасом 300 мс. Тихая речь и внутренние паузы сохраняются.
- При отсутствии/ошибке/таймауте ffmpeg используется WAV; пустое аудио не выдаётся за вопрос.
- На синтетическом примере: 8 с PCM 256 КБ → 23,5 КБ Opus за 88 мс;
  30 с PCM 960 КБ → 88,1 КБ за 95 мс. Это размер/подготовка, не замер полной задержки ответа.
- Проверено: 64 теста; реальный API принял Opus с синтезированным русским вопросом и вернул правильный ответ.


## v0.2.0 — непрерывная подготовка подсказок

- Аудио отправляется в Gemini в реальном времени: PCM16, 16 кГц, чанки 20 мс.
- Фоновый снимок выбранного экрана обновляется каждые 1,5 с, JPEG quality 60,
  быстрый ресайз, цель до 100 КБ и media resolution LOW.
- Раздельные непрерывные контексты для ⌥Q (без изображений) и ⌥Z (со снимками).
- Серверный VAD: 350 мс тишины; нажатие в тихом хвосте фразы финализирует поток без полного ожидания VAD. Кнопка «Пауза потока» отключает фоновую передачу.
- ⌥Q/⌥Z показывают готовящуюся или готовую подсказку без повторной отправки буфера.
- При сбое остаются запрос по нажатию и REST-резерв. Показанный частичный ответ не переотправляется.
- Смена экрана, новая речь и сбой сети исключают соответствующие старые ответы.
- Для быстрых подсказок выбрана gemini-3.1-flash-live-preview с minimal thinking;
  модели полных ответов/кода сохранены.
- Реальные синтетические пробы дали около 1,2 с до текста по звуку на 3.1,
  около 1,5 с на 3.8. С финализацией по кнопке две пробы дали 0,845 и 1,300 с по звуку.
  Постоянные 0,5–0,8 с не подтверждены. Методика: [LATENCY.md](LATENCY.md).


- Проверено: 73 автоматических теста, нативный интерфейс паузы и реальные подключения/API-пробы.

## v0.1.0 — первая рабочая версия

Зафиксировано 20 октября 2026 года.

В пользовательском тесте всё работает; первый текст появляется примерно через
**3,5 секунды** после нажатия горячей клавиши. Это единичное наблюдение пользователя,
а не среднее по серии измерений. Режим, модель и условия сети для этого замера
отдельно не зафиксированы. Снижение задержки — следующая задача.

В этой версии:

- Короткая подсказка: **Option + Z**; подробный ответ / код: **Option + X**.
- Потоковый вывод ответа; Live-подсказки с переходом на обычный запрос при сбое.
- Снимок выбранного монитора и последние 8–60 секунд звука; отдельная кнопка «Только экран».
- Перемещаемые окна, сохранение расположения, выбор мониторов для окон и захвата.
- Управление API-ключами через интерфейс, хранение в Связке ключей macOS.
- Автоматическая смена доступного ключа после ошибки лимита до начала ответа.
- Запуск двойным щелчком по «Запустить.command».

Локальные проверки: 47 автоматических тестов. Тесты используют имитацию API,
не измеряют скорость Gemini и не расходуют квоты.
